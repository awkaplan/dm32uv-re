# fd6818.rdl: notes

Companion to `fd6818.rdl` (the FD6818B RF transceiver). The `.rdl` is the source of truth; this
page collects what does not fit on one register. Guide = "FD6818 Programming Guide" REV.1.0.0
(Chinese, vendor document, not distributed here); page numbers are its printed footers.

## How the firmware evidence was gathered

Every `bsr` in the stock program-flash image and the IRAM image was decoded and its target
compared with the three FD6818 entry points: `fd6818b_reg_write` (IRAM `0x0002c2f4`),
`fd6818_reg_read` (IRAM `0x0002c33c`) and `fd6818b_reg_write_wrapper` (`0x0300de60`, REG_40H
only). That gives 342 call sites: 297 writes (275 flash, 22 IRAM), 42 reads, 3 wrapper calls. No
literal pointer to either primitive exists, so no indirect calls were found. At each site the
register number and value were recovered from the instructions in the same basic block; the ten
sites whose register number comes from a callee-saved register were resolved by hand (`0x02`,
`0x09`, `0x0c`, `0x5f`, `0x71`).

`[unreached]` in a `fw_writes`/`fw_reads` string means: the function has no `bsr` to it and no
pointer to it anywhere in either image, or it is a case of a switch inside such a function, or the
write sits on a branch its only caller never takes (`fd6818b_pa_power_level_select` and the mode-1
half of `fd6818b_mode_register_table_apply`, both called once with argument 0). These look like
vendor driver code linked but unused: the crystal setup (REG_3BH/3CH/3DH/41H for 13, 19.2, 12.8,
25.6, 38.4 MHz), REG_31H (TOT), REG_44H/45H/54H/55H/74H/75H, REG_27H/29H/4BH/53H.

## Paging

- 3-wire: `R/W | ADDR[6:0] | DATA[15:0]`. Registers `0x80`-`0xFF` need `WRITE(0x7F, 1)` and are then
  addressed as `reg - 0x80`; `WRITE(0x7F, 0)` returns to page 0 (default). The guide's examples
  write page-1 registers as `WRITE(I2C | 0xNN, ...)`, `I2C = 0x80`.
- 2-wire (I2C-style, device address `0101110`/`1110001` by the SCN pin): 8-bit register address,
  no paging. The DM-32UV uses the 3-wire bus.
- REG_7FH is a write-only command; a real radio reads 0 from it.
- Stock never writes REG_7FH, and its write primitive sends the register byte as-is (bit 7 would
  turn a write into a read), so **stock firmware only ever uses page 0**. Every page-1 register in
  the file is datasheet-only.
- In the `.rdl`: `page0` regfile @ `0x000`, `page1` @ `0x100`; byte address = register number x 2 in
  both, `wire_addr` = the 7-bit number clocked out. `gen_rdl.py` emits `enum fd6818_page0` /
  `enum fd6818_page1` from `wire_addr`.

## FD6818B vs the FD6818 guide

| Register | Guide (FD6818) | FD6818B (stock firmware / real radio) |
|---|---|---|
| REG_00H | chip_id `0x6818` | reads `0x4819` (hardware) |
| enable word | REG_03H | `0x30`; stock never touches `0x03`; same bit layout and words (`0xBFF1` RX, `0xC1FE` TX) |
| REG_28H | default `0x003F` | `[15:8]` is live GPIO input (`0x6b..`); `[5:0]` writable |
| REG_40H | default `0x3808` | reads `dev_en=1, dev_sh=4` after soft reset; stock writes `x | 0x3400` |
| REG_7DH | `dig_gain_rx[12:8]`, `[7:0]` reserved | stock writes `(t & 0x1f) | 0xe340`: a selectable 5-bit value in `[4:0]` |
| REG_0CH | `[15:10]` reserved | stock reads `[11:10]`, `[13:12]`, `[15:14]` |
| REG_24H | MCBSP input selects | stock writes `0x8c..` next to REG_0x21 in DTMF coefficient loads |
| REG_5CH | type byte `0x01`/`0x21`/`0x61` | stock writes `0x65`/`0x25` |
| (none) | registers `0x0A 0x0D 0x0E 0x10-0x12 0x14 0x1F 0x20 0x21 0x29 0x2B 0x30 0x32 0x33 0x37 0x3E 0x45 0x49 0x4A 0x4E 0x55 0x58 0x63 0x68-0x6A 0x74 0x77 0x7B 0x7C` | used by stock; not in the guide |

Registers the guide documents but stock never writes: REG_03H, 04H, 18H, 19H (PA bias), 1AH (band),
22H, 23H, 26H, 28H, 2CH, 2DH, 3AH, 46H, 56H, 73H (AFC), 76H, 79H, 7AH, 7FH and all of page 1.
TX power and band selection must therefore reach the RF chain some other way on this board.

## A correction this file makes

The soft-float chain in `rf_channel_frequency_apply` (`x * 2.064888 + 0.5`, constant at
`0x0307694c`) feeding `fd6818b_program_divider` had been read as an FM-tuner PLL divider. It
writes **REG_07H**, the CTCSS/CDCSS-rate word: 2.064888 = 2^27 / 65,000,000, the guide's
`freq(Hz) * 2^27 / 6.5e6` with the frequency in 0.1 Hz. The same path writes `0x0ad7`, the guide's
"134.4 Hz DCS rate" value. `fd6818b_write_cdcss_code_reg08` likewise writes REG_08H (CDCSS code, low then
high half).

## Inconsistencies inside the guide

- REG_00H: summary says read-only; the configuration flow writes `0x8000`/`0x0000` (soft reset).
- REG_02H source codes: the interrupt section (p.51) has 8 = DTMF/SELCALL, 7 = PLL lock lost;
  the summary (p.56-57) has 8 = PLL lock lost, 4 = DTMF/SELCALL.
- REG_3AH: bandwidth examples write it; the revision history says that setting was removed.
- REG_43H `wb` at `[5]` (p.10, p.21) vs `[5:2]` reserved (summary).
- REG_53H gain-shift polarity: `111 = max` (summary) vs `000 = max` (p.13, p.24).
- REG_59H bit 12 `fsk_rx_en` described as "Enable FSK TX", bit 11 the reverse; data-invert
  directions also swap between p.34 and p.64.
- REG_90H soft-mute `rate`/`atten` positions swap between the summary and p.48.
- REG_97H `cmpd_tx_gain` step 0.5 dB (summary) vs 1 dB (p.26).
- REG_2CH: `ext_lna_gain[4:0]` (p.47) vs a raw filter constant in the audio-response example (p.25).

## Open questions

- Meaning of the undocumented registers, in particular REG_0x37 (written before every enable),
  REG_0x32 / 0x0D / 0x0E (a start bit and a band-windowed 11-bit result), REG_0x33/34H/35H
  (indexed 4-bit selectors), REG_0x68-0x6A, and REG_0CH `[15:10]`.
- Whether REG_03H exists on the FD6818B at all, and whether the guide's page-1 registers are at the
  same numbers on it (never exercised).
- REG_40H: FD6818B reset value vs a value retained from earlier operation.
- REG_7DH: which of `[12:8]` / `[4:0]` is the gain on the FD6818B.
- How stock sets TX power and band, given it writes neither REG_19H/28H nor REG_1AH.
- Chip ID `0x4819` is from one unit; a second unit or an FD6818B datasheet would confirm it as the
  part's value.
